# V0.3.2a 正式地图图集修正版

## 结论

当前 V0.3.2 场景接入功能已经跑通，但美术评审不通过。

问题不是缺少摆件，而是地图主视觉仍由程序底色、程序笔刷、半透明形状决定。正式摆件和角色只是贴在这层原型底图上，因此画面仍像原型地图。

V0.3.2a 改为：先制作正式地图图集，再用图集做无限循环。

## 当前问题

1. 程序底色太明显  
   大面积绿色/紫色渐变和半透明笔刷块让画面像调试底图，不像敦煌壁画场景。

2. 底图和摆件不属于同一套视觉语言  
   摆件是相对细的 WebP 图件，背景是程序色块，两者质感不统一。

3. 无限延展不应该靠整图平铺  
   整张场景图不是无缝 tile，平铺会出现矩形明暗块；不平铺又会退回程序底色。

4. 剧情点位虽然变明显了，但还像 UI 标记  
   点位应像场景物件本身发出叙事信号，而不是普通摆件上加一个“缘”字。

## 正确路线

### 1. 地图图集先行

每套出生场景和公共荒境都要有一组可拼接图件：

- 地表 tile：用于铺满大面积地图。
- 地表变化 tile：用于打破重复。
- 边缘过渡 tile：用于不同地貌之间融合。
- 大型 decal：用于局部叙事氛围。
- 普通摆件：草、石、骨、残旗、灵火等。
- 剧情点位：主线、支线、轮回记忆。

### 2. 无限地图再接入

地图 chunk 不再绘制程序底色为主，而是：

1. 选择场景包。
2. 按 chunk 坐标稳定随机选地表 tile。
3. 在 tile 上叠边缘/过渡/decal。
4. 按规则放普通摆件。
5. 单独放剧情点位。

### 3. 程序绘制退为辅助

Canvas 程序层只保留：

- 屏幕暗角。
- 少量空气尘粒。
- 低透明远景线。
- 运行时特效。

禁止程序层承担主地貌。

## 图集规格

- 地表 tile：512x512 WebP，边缘无缝或弱接缝。
- 大型 decal：512x256 / 768x384 透明 WebP。
- 普通摆件：128x128 / 256x256 透明 WebP。
- 剧情点位：320x320 透明 WebP，至少 idle/ready 两态。
- 单场景包首版预算：300KB - 600KB。
- V0.3.2a 全量首包预算：2MB 以内。

## Tile 拼接规范

正式地图采用 tile 拼接为主，噪点与程序规则为辅。噪点只负责选择、密度、扰动和分布，不负责直接生成主地表。

### 一致性硬规则

1. 统一光照  
   基础 tile 内不能有明显中心光、边缘暗角或单向强阴影。全屏光照、暗角和空气感由 Canvas 统一处理。

2. 统一色盘  
   每个场景包固定 4-6 个主色，tile 之间平均明度接近，避免拼接后出现棋盘格。

3. 边缘弱无缝  
   tile 四边不能有大形状切断。边缘纹理可以轻微跨边，但必须低对比、低透明、可循环。

4. 大元素不进基础 tile  
   雾池、剑痕、灵井、残碑、草丛、骨堆、赤裂、碑群都放到 decal / prop / event 层，不能放进 base tile。

5. 笔触颗粒统一  
   所有 tile 都使用旧壁画颗粒、矿物颜料、手绘线痕。不能一部分像水彩、一部分像矢量、一部分像油画。

6. 图层职责清楚  
   - `base`：基础地貌肌理。
   - `variant`：轻微变化，不改变地貌身份。
   - `edge`：不同地貌之间的过渡。
   - `decal`：大形状氛围叠加。
   - `prop`：普通摆件。
   - `event`：剧情点位。

7. 先拼接评审，再接游戏  
   每个场景包生成后必须先做 tile style sheet 和 3x3 拼接预览，确认没有明显接缝和风格漂移，再接入 runtime。

### 场景包色盘约束

- 剑冢荒境：赭土、烟灰、冷金、暗青。
- 青丘残梦：灰紫、墨青、旧金、淡绯。
- 百草荒泽：墨绿、赤土、药青、旧金。
- 荒境深处：赭石、灰褐、青绿、烟紫。

## 美术方向

地图应接近“古朴厚重的敦煌矿物壁画地貌”：

- 地表不是纯色块，而是带矿物颗粒、旧壁画磨损、手绘纹路。
- 色彩压住，但保留赭石、青绿、旧金、灰紫的层次。
- 图件边缘要柔和，不出现现代矢量形状感。
- 场景摆件和地表要像同一张画里长出来的，不像贴图贴上去。

## V0.3.2a 验收标准

1. 截图第一眼看不到程序底色。
2. 移动 2 分钟后不出现矩形块状接缝。
3. 三主角出生场景有明确差异。
4. 场景摆件与地表色彩、明度、材质统一。
5. 剧情点位不依赖“缘”字也能看出可交互。
6. 运行压力仍保持 60 FPS 以上。
