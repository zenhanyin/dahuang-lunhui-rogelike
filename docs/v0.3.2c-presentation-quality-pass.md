# V0.3.2c 表现层质感推进记录

日期：2026-07-27

## 本轮目标

进一步减少程序占位感，把剧情点位从“canvas 临时画圈和写字”推进到正式 WebP 图件接入，并继续修正 UI 文本区域压框、错位的问题。

## 已完成

- 新增剧情点位正式小图集：
  - `event_marker_under_idle.webp`
  - `event_marker_under_ready.webp`
  - `event_marker_under_done.webp`
  - `event_marker_badge_idle.webp`
  - `event_marker_badge_ready.webp`
  - `event_marker_badge_done.webp`
  - `event_marker_prompt_ready.webp`
- 运行时剧情点位绘制改为优先使用正式图件，加载失败时才回退到旧 canvas 绘制。
- 剧情点位保留三态：未触发、可触发、已记录。
- HUD 内容区向卷轴内芯重排，减少底部文字压住花边的问题。
- 升级卡牌正文区域收窄，长文不再明显顶到卡框边缘。
- 更新缓存版本到 `0.3.2c-story-marker-pass`。

## 验证

- `tools/smoke-test.mjs`：通过。
- `tools/audit-style-systems.mjs`：通过，无原型资源引用回流。
- `tools/visual-run.mjs`：通过，覆盖开局、战斗、升级卡、暂停、构筑、剧情、结算、手机截图。
- `tools/visual-qingqiu-loop.mjs`：通过，青丘 tile 循环和事件点位仍正常。
- `tools/stress-probe.mjs`：通过，60 怪基础压力约 4ms/帧；真实视觉脚本有特效叠加时约 12ms/帧。

## 当前画面判断

青丘地表 tile、低对比 decal 和静态/动态摆件已经可以作为后续场景资产模板。剧情点位比上一版更清楚，也不再完全依赖浮字表达。

仍不应把当前 UI 当作最终质量：

- HUD 使用正式图件，但文本安全区仍然偏紧，后续最好按 HUD 图件重新定义专用内容区域。
- 当前构筑 UI 是功能可用版，仍借用剧情卷轴框，不够像独立系统。
- 结算框内容偏左上，奖励章和按钮间距需要再排。
- 暂停框可用，但禁用按钮和可点击按钮的层级还不够清晰。
- 升级卡牌已明显改善，但长文仍建议从配置层限制字数。
- 技能动特和音效反馈仍是主要短板，爽感还没真正起来。

## 下一步建议

V0.3.2d 可以继续做 UI 图件的“内容安全区重标”：

- HUD 专门重排：血量、修为、境界、时间、斩妖保持清晰，构筑摘要彻底移出。
- 结算框专门排版：轮回点、斩妖、构筑回顾、再入轮回按钮分区。
- 构筑 UI 专用 atlas：流派、功法等级、进化线、剧情印记分区。
- 暂停菜单强化：继续、当前构筑、图鉴预留、设置预留、退出预留的视觉层级统一。
- 技能/资源图标再统一一轮，避免和敦煌 UI 主风格脱节。
