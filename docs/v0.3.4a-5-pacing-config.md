# V0.3.4a-5 Pacing Config Pass

Date: 2026-08-09

Goal: move first chapter rhythm tuning out of runtime logic and into a readable config table.

## Config Entry

The main table is `CONFIG.chapterOne` in `src/config.js`.

It now owns:

- `timeline`: first story, elite wave, second story, Boss warning, Boss spawn and chapter time limit.
- `pacing.spawn`: normal spawn delay, minimum delay and time-based ramp.
- `pacing.xp`: first level XP, growth curve, additive XP growth and pickup range.
- `pacing.levelUp`: the automatic baseline growth granted on each level-up, currently focused on making the primary sword attack visibly stronger.
- `pacing.runtimeLimits`: HTML pressure caps for enemies, projectiles, drops, pulses, damage text and effects.
- `pressure.spawnMultiplier`: how fast the normal spawn loop accelerates at each chapter phase.
- `pressure.extraSpawnChance`: extra spawn bursts after important chapter beats.
- `pressure.randomEliteChance`: random elite pressure after the fixed elite beat.
- `eliteWave`: fixed elite wave spawn angle, distance and per-map enemy stats.
- `boss`: Boss spawn distance, HP formula, damage, speed, phase thresholds, rupture/shockwave values and summon pool.
- `boss.phaseGateDuration`: short HP gate after each phase transition, used to prevent high burst builds from skipping Boss phases entirely.
- `stories`: first and second memory text plus reward hooks for Xuanyuan and Qingqiu.

## Current Feel Target

This pass slightly lowers early and Boss pressure:

- Opening is calmer so the first upgrade and first story point are readable.
- Elite wave still arrives at 42s, but fixed elite stats are slightly softer.
- Boss enters at 120s and still has phases. Real-play probe showed the first reduced HP pass died too fast, so Boss HP was raised back into a clearer chapter-objective range while keeping damage softer.
- Random elite noise is lower before Boss so the chapter structure is easier to read.

## How To Tune Next

Use these knobs first:

- Too chaotic early: lower `pressure.spawnMultiplier.opening` and `afterFirstStory`.
- Too many enemies or browser stutter: lower `pacing.runtimeLimits.maxEnemies`, `maxProjectiles`, or raise `pacing.spawn.minDelay`.
- Leveling feels too slow: lower `pacing.xp.base`, `pacing.xp.growth`, or `pacing.xp.add`.
- Level-up does not feel stronger: raise `pacing.levelUp.swordDamage`, `swordRange`, or lower `swordDelayMul`.
- First elite feels unfair: lower `eliteWave.byMap.*.hp`, `damage` or `speed`.
- Boss drags: lower `boss.hpBase` or `boss.hpPerLevel`.
- Boss lacks pressure: raise `boss.phases.*.speedScale`, `groundRupture.enrage.count` or `shockwave.enrage.damage`.
- Boss dies too fast or skips phases: raise `boss.phaseGateDuration` before raising raw HP.
- Player misses story rhythm: move `timeline.firstStory` earlier or increase story point prompt/VFX instead of increasing spawn pressure.

## Regression

`tools/probe-chapter-v034a4.mjs` now derives Boss HP expectations from `CONFIG.chapterOne.boss`, so future tuning should not require changing the test when only numbers move.

`tools/probe-pacing-v034a5.mjs` runs both active starts through a lightweight 140-second real-update simulation. It auto-selects upgrade cards and steps onto story points, then reports level, enemies, resources, memories and Boss state at chapter checkpoints.

- Both starts can record the first and second memory before Boss.
- No safety heal assist was needed in the 140s pacing probe.
- Enemy count stays under the HTML pressure budget.
