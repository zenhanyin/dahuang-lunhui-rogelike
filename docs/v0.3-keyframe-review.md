## 规范基准

V0.3 视觉核心是“古朴厚重的敦煌矿物壁画风”。

必须保留：

- 古朴、厚重、壁画、矿物颜料、残卷、碑拓、经页。
- 石青、石绿、赭石、朱砂、藤黄、老墙灰。
- 低饱和整体色调，局部用紫雾、灵火、丹火做神异高亮。
- 云气线描、莲纹、飞天飘带、残损边缘、壁画颗粒与剥落感。

必须避免：

- 太亮，变成轻国风。
- 太黑，变成暗黑仙侠。
- 太金属，变成修仙手游。
- 太干净，变成现代网页/手游卡片。
- 常驻底部大技能栏误导玩家点击自动功法。

核心 UI 层级：

- 左上：角色状态 HUD。
- 右上：灵髓、丹火、暂停。
- 右下：唯一主动神通按钮。
- 边缘：轻量构筑摘要。
- 中央：升级、剧情、事件、暂停、结算弹层。

## 单张评审

### 横屏战斗 UI 01

文件：`assets/concepts/v0.3.0-combat-ui-hierarchy-01.png`

符合项：

- 厚重感最强，接近古壁画和大荒荒境感。
- UI 层级正确：左上 HUD、右上资源、右下神通、底部只有轻量构筑摘要。
- 没有出现常驻底部大技能栏，符合吸血鬼Like构筑查看逻辑。
- 场景摆件、残碑、荒祠、紫雾、灵火都接近 V0.3 叙事点位方向。
- 伤害飘字有碑拓和朱砂味，比默认网页数字更接近目标。

问题：

- 整体过暗，角色、敌人和地面层次容易吃掉。
- 暗部面积偏大，风险是滑向暗黑仙侠。
- 地图信息略碎，正式运行时可能影响走位判断。

结论：

- 可作为“厚重感、构图层级、神通按钮位置”的参考。
- 不可直接作为明暗基准。

### 升级卡牌 UI 01

文件：`assets/concepts/v0.3.0-upgrade-cards-01.png`

符合项：

- 三选一层级清楚。
- 卡牌像壁龛/经页，比当前运行时卡牌更贴合敦煌方向。
- 略过悟道作为次级入口，逻辑正确。
- 背景战斗被压住，决策焦点明确。

问题：

- 整体同样偏暗。
- 卡牌文字区可读性一般。
- 外围装饰和暗部叠加后略重，可能压住卡牌内容。

结论：

- 可作为“卡牌形制”的参考。
- 正式卡牌应提高文字区明度并减少暗部叠加。

### 竖屏战斗 UI 01

文件：`assets/concepts/v0.3.0-mobile-combat-ui-01.png`

符合项：

- 竖屏布局方向成立：顶部压缩 HUD、右上资源、右下神通。
- 左下摇杆按触屏出现的表现正确，没有做成永久固定大面板。
- 中央战斗区域相对清晰。
- 剧情点位提示可以从残碑/灵火附近读出。

问题：

- 顶部 HUD 仍偏大，正式手机端可能占用过多视野。
- 底部状态条可以再压缩，避免和神通按钮抢空间。
- 角色和怪物尺寸比例仍需以真实 Web 运行测试校准。

结论：

- 可作为竖屏 UI 方向参考。
- 后续实现时应把 HUD 做得更轻，并把移动转盘设置为按下显示、松手淡出。

### 横屏战斗 UI 02

文件：`assets/concepts/v0.3.0-combat-ui-hierarchy-02.png`

符合项：

- 明暗度比 01 更适合实际游戏。
- 地面纹理、角色、敌人、UI 文字更清楚。
- 仍保留石青、赭色、朱砂、矿物紫雾等核心色彩。
- UI 层级仍正确，没有底部大技能栏。
- 右下神通按钮辨识度高。

问题：

- 比 01 稍微轻了一点，古朴厚重感略下降。
- 地面亮度提升后，局部有“修复壁画/插画背景”的轻感。
- 正式资源需要控制背景细节，避免运行时过密。

结论：

- 当前最适合作为“实际运行明暗度基准”。
- 正式方向建议采用：02 的明度 + 01 的厚重纹理。

### 升级卡牌 UI 02

文件：`assets/concepts/v0.3.0-upgrade-cards-02.png`

符合项：

- 卡牌可读性明显提升。
- 三选一焦点清楚，免费悟道和略过悟道逻辑更容易理解。
- 卡牌颜色比当前运行时更接近敦煌 UI。
- 背景仍能感到战斗存在，但不会抢 UI 焦点。

问题：

- 卡牌边框略华丽，存在向手游金属 UI 靠近的风险。
- 中央选中光略强，正式版本要压住，不做霓虹高亮。
- 卡牌整体偏完整，残损边缘和旧经页质感可以更强。

结论：

- 当前最适合作为“升级卡牌布局和明度基准”。
- 正式切图时应减少外圈繁饰，增强纸张纤维、残损边缘和壁画颗粒。

### 剧情点位对话 UI 01

文件：`assets/concepts/v0.3.0-story-dialogue-01.png`

符合项：

- 残碑触发后的叙事感成立，玩家能理解这是剧情点位，不是普通弹窗。
- 卷轴对话框留白充足，正文和选择按钮可读性较好。
- 点位图标、章节线索、灵髓消耗关系较清楚。
- 背景战斗仍可见，说明这是局内事件，而不是独立菜单。

问题：

- 背景压暗略重，正式运行时可以减轻遮罩，避免画面闷。
- 右下神通仍占视觉注意力，剧情弹层出现时应进一步弱化。
- 正文文本量需要控制，避免移动端难读。

结论：

- 可作为 V0.3 剧情对话 UI 的主要参考。
- 正式实现时应保留“点位插画 + 标题 + 短正文 + 两个选择”的结构。

### 随机事件 UI 01

文件：`assets/concepts/v0.3.0-random-event-01.png`

符合项：

- 荒祠事件的祝福/诅咒二选一表达明确。
- 灵髓消耗、丹火奖励、敌潮增强等玩法后果可被感知。
- 左右选择用石绿和朱砂区分，适合后续机制反馈。
- 面板不像商店，比较符合剧情事件。

问题：

- 面板面积偏大，横屏可接受，竖屏需要重新布局。
- 选择按钮和说明区可以进一步分层，避免文字堆在一起。
- 背景神通按钮应在事件弹层里降权。

结论：

- 可作为随机事件 UI 的方向基准。
- 正式实现建议采用“两选一事件牌”，不要复用升级三选一卡牌。

### 轮回结算 UI 01

文件：`assets/concepts/v0.3.0-reincarnation-result-01.png`

符合项：

- 与普通 Game Over 区分明显，更像“轮回命簿”。
- 本世经历、记忆碎片、章节线索、功法成型、轮回点都有位置。
- 右侧记忆条目能承担剧情推进感。
- 情绪不是失败惩罚，而是“此世记录”，符合轮回机制。

问题：

- 信息密度较高，正式版需要按优先级分区。
- 图标和条目可读性需要在真实分辨率下验证。
- 按钮文案要进一步统一：再入荒境、查看记忆、暂回命簿。

结论：

- 可作为轮回结算 UI 的主要参考。
- 这是 V0.3 叙事差异化的关键界面，优先级高。

### 暂停构筑 UI 01

文件：`assets/concepts/v0.3.0-pause-build-01.png`

符合项：

- 清楚解释了“当前 build 在暂停界面查看”，能解决底部技能栏争议。
- 功法、机缘、印记三类构筑信息区分明确。
- 角色状态、资源、功法等级和机制说明都能放进去。
- 按钮层级清楚，继续为主按钮。

问题：

- 面板仍偏大，正式横屏可以略压缩，竖屏需要拆成分页。
- 功法列表可读性好，但运行时不要做得太像可点击战斗技能。
- 装饰还可以减少，让信息更利落。

结论：

- 可作为暂停构筑 UI 的核心结构参考。
- 后续应直接替代战斗底部大技能栏的信息职能。

### 出生选择 UI 02

文件：`assets/concepts/v0.3.0-lineage-select-02.png`

符合项：

- 三主角选择结构清楚，能和文游版本区分为动作生存开局。
- 命格、初始神通、气血、身法都有明确位置。
- 角色立绘不再是纯剪影，保留了彩绘纸片精灵的可读性。
- “开始入荒”和“查看命簿”入口符合 V0.3 叙事构筑方向。

问题：

- 整体明度略回落，正式版应参考战斗 UI 02 再提一点中间调。
- 卡牌之间的装饰密度偏高，移动端需要简化。
- “初始神通”与“自动功法”的区别还可以更明确。

结论：

- 可作为出生选择结构参考。
- 正式版需提高中间调明度，并简化边框装饰。

### 剧情故事/命簿 UI 01

文件：`assets/concepts/v0.3.0-story-codex-01.png`

符合项：

- 命簿阅读界面气质稳定，适合承接轮回结算。

- 锁定条目、记忆条目、剧情点位解锁都能表达 RPG 叙事推进。
- 风格古朴，不像现代任务日志。

- 正文区域在移动端需要改成分页或单列。
- 部分装饰性飞天背景可以降噪，避免干扰阅读。

结论：

- 可作为剧情故事 UI 的主要参考。

### 青丘魇母 Boss 本体 01

文件：`assets/concepts/v0.3.0-boss-qingqiu-nightmare-mother-01.png`

符合项：

- 作为 Boss 设定图比场景定帧更清楚，能看到正面、侧面、面部、尾焰和挂饰细节。
- 多尾紫雾、狐火、朱砂眼、祭祀挂饰符合青丘梦魇主题。

### 暂停/继续按钮组件 01

文件：`assets/concepts/v0.3.0-pause-buttons-01.png`

符合项：

- 成功解决现代 `Ⅱ` 图标违和问题。
- 战斗态暂停按钮改为小型“止/暂”印章，更贴合敦煌法印和系统控制。
- 暂停态主操作用横向“继续”残卷牌，不再和神通圆章混淆。
- 设置、记忆、退出本世等次级按钮形态统一，适合 HTML 小 WebP 切片。

问题：

- “止”和“暂”需要二选一，避免运行时符号不统一。
- 小尺寸下印章字可读性要验证。
- 悬停光效可保留，但不能做成高亮霓虹。

结论：

- 后续实现应废弃 `Ⅱ` 作为主要视觉符号。
- 推荐：战斗态用“暂”印章；暂停弹层主按钮用“继续”横牌。

### 轻量 UI 单件稿 01

文件：`assets/concepts/v0.3.0-ui-components-lightweight-01.png`

- 可作为 V0.3.1 正式 UI 组件生产参考。
- 资产策略：按组件导出小 WebP，避免整张大图常驻内存。

## 与 V0.3 规范比对

### 美术风格

达成：

- 敦煌壁画、矿物颜料、石青石绿、朱砂、紫雾、灵火已经能被识别。
- UI 从现代卡片向残卷、经页、壁龛转变。
- 角色和怪物开始具备彩绘纸片精灵方向。

不足：

- 01 偏暗，02 偏轻，中间值尚未完全稳定。
- 场景细节较密，正式游戏里需要减少噪声。
- UI 装饰容易过华丽，需要压制金属感。

确定方向：

- 明度以 02 为基准。
- 厚重纹理以 01 为基准。
- 色彩不再继续压暗，也不再大幅提亮。
- 正式图集应控制为“旧壁画明度”，不是“暗黑副本”也不是“亮色国风”。

### UI 层级

达成：

- 左上 HUD、右上资源、右下神通的层级成立。
- 底部常驻技能栏已经在定帧中弱化或取消。
- 升级卡牌决策焦点清楚。
- 竖屏触控区域方向成立。

不足：

- 横屏 HUD 在一些画面里仍然略大。
- 竖屏 HUD 仍需更省空间。
- 轻量构筑摘要需要继续定义，不应像技能栏。

确定方向：

- 战斗中只保留一个主动神通按钮。
- 自动功法不做大按钮。
- 构筑查看放到升级、暂停、结算里。
- 战斗中只显示小图标/等级珠/进化提示。

### 玩法表达

达成：

- 灵髓、丹火、神通在 UI 上已有明确位置。
- 升级三选一视觉上比当前运行时更有仪式感。
- 剧情点位从残碑、灵火、荒祠等场景物件中开始可见。

不足：

- 定帧里还没有表达“剧情点位对话/随机事件 UI”。
- 没有表达“轮回结算/记忆碎片/章节线索”的界面。
- 神通充能逻辑还只停留在视觉按钮，没有完整状态表达。

确定方向：

- 下一批定帧必须补剧情对话、随机事件、轮回结算、暂停构筑。
- 神通按钮需要有充能环、可用状态、不可用状态。
- 灵髓和丹火要通过 UI 文案/图标/反馈明确用途。

## 下一轮定帧需求

优先补齐四张：

- Boss 本体设定定帧：青丘魇母需要更有梦魇压迫和神话异化，减少漂亮妖姬感。
- 竖屏升级卡牌 UI：验证三选一在手机下半屏的阅读与触控。
- 竖屏剧情事件 UI：验证事件选择不遮挡触控和战斗信息。
- 正式 UI 组件单件稿：HUD、资源牌、神通按钮、卡牌、对话框、结算面板逐个生成或绘制。

生成约束：

- 明度参考横屏战斗 02。
- 纹理参考横屏战斗 01。
- 卡牌可读性参考升级卡牌 02。
- 装饰复杂度比升级卡牌 02 降低 15%-25%。
- 文字区必须留足清晰阅读空间。
- 不出现购买升级卡牌的视觉暗示。
- 不出现常驻技能栏。
- 竖屏 UI 不固定摇杆，只表现触屏按下时的临时圆盘。
- 剧情对话采用“点位插画 + 标题 + 短正文 + 1-2 个选择”。
- 随机事件采用“两选一事件牌”，不要复用升级三选一卡牌。
- 轮回结算必须突出“本世经历”和“记忆留下痕迹”。
- 暂停构筑承担 build 查看职责，不承担战斗技能释放职责。
- 暂停入口不再使用现代 `Ⅱ` 图标，改用“暂”或“止”印章。
- 暂停后的继续操作使用横向“继续”残卷按钮，不使用圆形法印。
- 正式 UI 资产按小组件输出 WebP，不直接加载整张大图集或概念板。

## 对开发实现的影响

V0.3.0 可以先进入以下实现准备：

- 建立正式资源目录和 manifest。
- 把当前 `assets/generated/runtime-webp` 标记为验证资产。

- HUD 残卷。
- 资源牌。
- 神通法印。
- 升级卡牌。
- 出生选择。
- 剧情对话。
- 暂停构筑。
