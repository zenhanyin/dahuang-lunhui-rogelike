# V0.3.2b UI 收口与点位反馈评审

## 本版目标

V0.3.2b 的目标是把局内 UI 从“原型信息堆叠”收回到正式玩法结构：

- 战斗中只保留必要 HUD：血量、修为、境界、时间、斩妖。
- 构筑信息不再常驻底部技能栏，改为暂停中的独立入口。
- 暂停框承担系统入口，不混入状态条。
- 剧情弹框出现时弱化 HUD，让叙事 UI 成为主视觉。
- 剧情点位具备未触发、可触发、已记录三态。
- 手机竖屏不继续强行套桌面 UI，单独列入 V0.3.5。

## 已完成

- 移除底部常驻技能栏展示，局内仅保留等级章与冲刺章。
- 暂停框改为：继续、当前构筑、图鉴预留、设置预留、退出预留。
- 新增“当局构筑”弹层，显示本局已获得功法、路线层数和进化提示。
- 升级选择、剧情、构筑、结算弹层打开时淡化 HUD 和资源框。
- 剧情点位渲染增加状态差异：未触发、靠近可触发、已记录。
- 自动跑测脚本补充暂停和构筑截图。

## 跑测结果

- `tools/smoke-test.mjs`：通过。
- `tools/audit-style-systems.mjs`：通过，无缺失运行时资源，无旧 UI 禁用路径引用。
- `tools/visual-run.mjs`：通过，无 JS 错误，压力探针约 10.32ms/帧。
- `tools/visual-mobile.mjs`：通过基础可运行探针，但不是正式手机 UI。

## 当前观感结论

整体方向比上一版清楚：玩家不会再误以为底部技能栏是吸血鬼like的核心构筑区，构筑被放进暂停入口后逻辑更合理。

仍需注意：

- HUD 当前仍依赖大卷轴图件，视觉占屏偏重；后续应补一张更轻的正式 HUD 小卷轴，而不是继续 CSS 缩放。
- 当局构筑面板已可用，但还只是第一版“构筑札记”，缺少图标化流派、进化线节点和剧情印记分区。
- 剧情点位有三态和提示，但事件点位的轮廓、触发光、已记录状态还需要更强的专属图件。
- 结算框已经正式化，但还缺“轮回记忆 / 解锁 / 构筑回顾”的叙事结算内容。
- 手机端现在只保证能跑，正式竖屏布局必须单独做。

## 下一步建议

### P0：V0.3.2c 事件点位完成度

- 剧情点位专属 atlas：未触发、可触发、已记录三态。
- 靠近提示从简单文字升级为低亮碑文/狐火/残线浮现。
- 已记录点位弱化，但仍能让玩家知道这里曾被记入轮回。
- 控制事件点密度，避免地图上“缘”字过多。

### P1：V0.3.3 构筑机制版

- 构筑分为功法、机缘、剧情印记三类。
- 当局构筑 UI 增加进化线节点和共鸣条件。
- 升级卡牌选择后，技能形态要产生可感知变化。
- 结算时显示本局构筑路线，作为下局轮回记忆的入口。

### P2：V0.3.4 怪潮与 Boss

- 加入 60-90 秒阶段节奏：普通潮、精英潮、事件潮、Boss 前兆。
- 第一章 Boss 触发与剧情线索绑定。
- Boss 需要专属 UI、音效和奖励。

### P3：V0.3.5 手机竖屏专项

- 单独做竖屏 HUD、升级卡、剧情事件、临时摇杆、神通按钮。
- 不直接缩放桌面 UI。
- 目标是手机完成 3-5 分钟局内循环。
