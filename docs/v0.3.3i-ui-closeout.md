# V0.3.3i UI 收口记录

日期：2026-07-31

## 本轮目标

把当前已经接入的正式 UI atlas 稳定为运行态权威样式，优先解决玩家反馈里反复出现的对齐、文字安全区、资源数字溢出、开局确认不明确等问题。

## 已完成

- 在 `styles.css` 末尾建立 `V0.3.3i UI system sync` 权威覆盖层，统一 HUD、资源框、开局卡牌、升级卡牌、剧情框、暂停与结算面板的运行态排版。
- V0.3.3l 已把桌面正式 UI 权威层拆到 `styles-ui.css`，并让入口加载顺序固定为 `styles.css` -> `styles-ui.css` -> `styles-mobile.css`。后续 UI 修正优先进入 `styles-ui.css` 或 `styles-mobile.css`，不要继续追加到历史 `styles.css`。
- V0.3.3i 二阶段已将 `styles.css` 中 `V0.3.2b` 之后的历史 UI 补丁区放入 `@media not all` 隔离层。旧规则保留为历史，但不再参与运行态布局。
- `tools/audit-style-systems.mjs` 已新增 UI 权威层检查：必须同时满足旧补丁隔离、`styles-ui.css` 桌面正式 UI 生效、`styles-mobile.css` 竖屏权威层生效。
- 修复开局选人卡人物图偏左：旧 `.lineage-art` 的 `left: 50%` 与 `transform: translateX(-50%)` 仍在影响正式卡牌，已在权威层取消并按 atlas 安全区居中。
- 修复资源框数字贴边与多位数风险：桌面资源数字改为固定安全宽度，向右收进正式资源框。
- 修复桌面开局按钮文本溢出：按钮宽度与文字安全区加大，支持“以轩辕遗剑开始”等动态文案。
- 保留竖屏开局确认逻辑：竖屏底部使用大按钮展示“以某角色开始”，避免玩家选中后不知道如何确认。

- `tools/audit-style-systems.mjs`：通过，未发现运行态缺失资源、原型资源引用或旧资源引用。
- `tools/audit-assets.mjs`：通过，未发现缺失资源、地图包 manifest 缺失或运行态原型引用。
- `tools/probe-ui-alignment.mjs`：通过，升级卡牌组与标题居中，资源框在右上角稳定。
- `tools/visual-run.mjs`：通过，桌面开局、升级卡牌、剧情框、暂停、结算、压力场景无 JS 错误。
- `tools/visual-mobile.mjs`：通过，竖屏移动 HUD、开局确认、升级选择无 JS 错误。

## 仍需注意

- `styles.css` 里保留了较多历史补丁块，目前已通过 `styles-ui.css` 和 `styles-mobile.css` 接管运行态。后续如果继续 UI 系统化，建议把 `styles.css` 物理拆成 `base.css`、`ui-atlas.css`、`mobile.css`，再逐段删除旧补丁。
- `build-site.js` 仍会在删除 `deploy-root` 时报 `EPERM`。这是部署目录占用问题，和 UI 收口无直接关系；部署前需要先释放或重建预览目录。
- 当前 UI atlas 的文字安全区已经可用，但卡牌标题、剧情标题、资源框数字仍应继续按 `docs/ui-atlas-safe-area-spec.md` 约束新增资源。
- 移动端已可用，但仍属于桌面 UI atlas 的竖屏适配。后续 V0.3.5 手机专项应补独立移动端 HUD 与卡牌 atlas。
## V0.3.3i 二阶段补记

- `styles.css` 中 V0.3.2b 之后的历史 UI 补丁已拆成两段 `@media not all` 隔离区：早期正式 UI 补丁区、后续移动端/卡牌/剧情/按钮补丁区。旧代码保留为历史记录，但不再参与运行态布局。
- 运行态 UI 权威文件固定为：桌面端 `styles-ui.css`，移动端 `styles-mobile.css`。后续 UI 修正优先进入这两个文件，不再继续在 `styles.css` 末尾叠补丁。
- `tools/audit-style-systems.mjs` 已加入 UI 权威检查：必须确认历史补丁隔离、桌面正式 UI 生效、移动端正式 UI 生效。
- 回归结果：`audit-style-systems`、`audit-assets`、`audit-ui-safe-areas`、`node --check src/game.js`、`visual-mobile` 均通过。
- 下一步建议：先用截图回归确认视觉无倒退，再把隔离区迁移到归档文档或物理删除，彻底降低旧 CSS 混入风险。
