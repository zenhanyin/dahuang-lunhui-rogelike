# V0.3 资产盘点与开发计划

项目名：大荒轮回录：荒境

盘点日期：2026-07-22

## 当前工程状态

当前项目已经进入“可跑玩法原型 + 第一轮 WebP 资产接入 + V0.3 规范定版前”的阶段。

已经具备：

- HTML Canvas 单机运行入口。
- 三个开局命格：轩辕遗剑、青丘巫女、神农丹徒。
- 自动攻击、拾取修为、升级三选一、略过悟道、基础敌潮。
- 随机场景摆件和跨屏地图雏形。
- 角色/小怪 WebP 行走帧已接入。
- 部分正式 UI WebP 资产已接入 CSS。
- 剧情点位弹层和章节线索逻辑已有雏形。
- 合成音效与简单音乐层已有，但不是正式音频资产。

仍处于原型或半成品：

- 场景图集风格还没有完全统一到古朴厚重敦煌矿物壁画风。
- UI 图集虽然接入了一版，但整体仍需要按新定帧重做。
- 底部功法槽仍在代码和界面中，需要改为轻量构筑摘要或移除。
- 技能图标、拾取物仍有 SVG 占位。
- 音乐和音效仍是 Web Audio 合成，不是正式资源。
- 剧情点位只有基础触发，还没有形成强叙事节奏。
- 轮回结算和长期记忆仍是入口预留。

## 资产盘点

### 概念图

目录：`assets/concepts`

数量：5 张 PNG，约 14.7 MB。

用途：

- 已有横屏战斗 UI、竖屏战斗 UI、卡牌/HUD 方向概念图。
- 可作为风格参考，但其中部分图偏亮或偏轻，需要以后续“古朴厚重敦煌矿物壁画风”规范为准。

处理建议：

- 保留为参考，不直接切入运行时。
- 下一批定帧图应按 V0.3 规范重新生成：压低亮度、压住金属感、增强壁画颗粒和残卷质感。

### 生成源图与处理图

目录：

- `assets/generated/raw`
- `assets/generated/processed`
- `assets/generated/qa`

现状：

- 有角色/怪物运动源图、场景摆件源图、UI 源图。
- 有去背景后的 processed 图。
- 有一张 runtime composite 预览图。

用途：

- 这是上一轮资产生成与切图的中间产物。
- 可继续追溯切图来源，但不应作为正式运行资源直接加载。

处理建议：

- 保留 raw 和 processed 作为历史来源。
- 后续正式资源重新建 `assets/runtime/webp` 或 `assets/runtime/v0.3`，避免继续混用 generated 目录。

### 运行时角色与怪物

目录：

- `assets/generated/runtime-webp/characters`
- `assets/generated/runtime-webp/enemies`

数量：

- 角色 WebP：42 个。
- 怪物 WebP：18 个。

已接入：

- `src/game.js` 当前直接加载 `assets/generated/runtime-webp` 下的角色与怪物帧。
- 包含 sword、witch、alchemist、wraith、elite、shadow 等。

问题：

- 风格仍偏“彩绘纸片/切图验证”，还没有达到正式精灵行走图标准。
- 方向只有左右，缺少完整 4 向或 8 向方案。
- 行走帧数量基本可验证动起来，但还不够正式。

下一步：

- 先保留可跑版本。
- 正式版角色做 3 主角，每个至少左右方向 4 帧，后续再扩展上下方向。
- 怪物先做普通妖、赤妖、精英妖三类，每类左右方向 3-4 帧。

### 地图与场景

目录：

- `assets/generated/runtime-webp/maps`
- `assets/maps`
- `assets/generated/runtime-webp/terrain`

现状：

- 已有 `wilds-final.webp`、`qingqiu-final.webp` 两张地图背景。
- 已有狐火、灵井、幻雾、裂隙、残碑、神龛、草、石、骨等 WebP 摆件。
- `src/game.js` 已接入 terrain 和 maps。

问题：

- 当前场景无限延展的拼接感仍明显。
- 地图大块色带、重复纹理和亮暗关系还不够自然。
- 场景没有形成章节层级：随机场景、剧情点位、Boss 场景还混在一起。

下一步：

- 重做第一章“青丘梦渊”地图资源包。
- 地面拆成低频大纹理 + 小型装饰摆件 + 剧情点位摆件。
- 增加地图 chunk 过渡规则，避免大块方形拼接。
- 剧情点位资源优先做残碑、灵井、荒祠、狐火、赤裂。

### UI 资产

目录：

- `assets/ui/atlas-v1`
- `assets/generated/runtime-webp/ui`
- `assets/generated/runtime-webp/ui/formal`
- `assets/ui/icons`

现状：

- `assets/ui/atlas-v1` 已有 HUD、资源牌、卡牌、命格卡、暂停面板、结算面板、神通按钮等 WebP。
- `styles.css` 当前主要加载 `assets/ui/atlas-v1`。
- `assets/generated/runtime-webp/ui/formal` 中有一批类似 formal UI 的旧版本。
- 图标仍多为 SVG。

问题：

- UI atlas-v1 不是最终风格，和最新定下的古朴厚重敦煌风仍有距离。
- 底部技能栏仍在，和吸血鬼Like直觉冲突。
- 卡牌、出生选择、剧情对话、暂停/设置、构筑查看的视觉层级还没统一。
- 图标语义不够清楚，灵髓/丹火/神通/功法类型需要重新设计。

下一步：

- 建 `assets/ui/v0.3` 或 `assets/runtime/webp/ui` 作为正式 UI 第一版。
- 先做 8 类核心 UI：HUD、资源牌、神通按钮、升级卡牌、出生选择、剧情对话、暂停设置、轮回结算。
- 移除底部大技能栏，改为右下神通 + 轻量构筑摘要。
- 图标优先 WebP 或统一风格 SVG，不再混用原型图标。

### 音频

目录：

- `assets/audio/music`
- `assets/audio/sfx`

现状：

- 目录基本为空，只有 `.gitkeep`。
- 当前音效由 `src/game.js` 通过 Web Audio 合成。

问题：

- 没有正式 BGM。
- 没有正式命中、击杀、拾取、升级、选卡、剧情点位、神通、Boss 音效。
- 打击反馈和仪式感不足。

下一步：

- 先做一版轻量音频验证包。
- BGM：探索循环、敌潮增强、Boss 压迫三层。
- SFX：命中、击杀、拾取、升级、选卡、略过、剧情点、神通。
- 保留 Web Audio 作为 fallback。

### 原型 SVG

## 当前做到哪一步

玩法层：V0.2.9 左右。

- 基础吸血鬼Like循环可以验证。
- 配表、随机地图、WebP 行走帧、升级三选一、略过补偿、剧情点位雏形都有。
- 但 V0.3 的章节叙事、轮回结算、Boss 推进还没完成。

美术层：V0.2 资产验证阶段。

- 已经从纯原型 SVG 过渡到 WebP 资产。
- 但正式敦煌厚重风格还没有稳定落到运行时。
- 当前 UI、场景、图标、卡牌仍需要重做第一版正式图集。

音乐音效层：V0.1 合成验证阶段。

- 有基础声音反馈。
- 没有正式音乐音效资源。

动特层：V0.2 机制可视化阶段。

- 飞剑、符咒、丹火、幻雾、拾取、飘字已有。
- 但美术化不足，和敦煌风格结合不够。

UI 层：V0.2.7 atlas 接入阶段。

- 一版 UI 图集已接入。
- 底部技能栏、卡牌弹层、出生选择、资源 UI 仍需要按 V0.3 重构。

## 下一步开发计划

### V0.3.0 资产归档与 UI 架构重构

目标：

- 明确哪些资源是运行时、哪些是概念图、哪些是历史生成物。
- 移除底部常驻大技能栏逻辑。
- 改成“右下神通 + 轻量构筑摘要 + 暂停查看构筑”。

任务：

- 建立正式资源目录：`assets/runtime/webp/ui`、`assets/runtime/webp/scene`、`assets/runtime/webp/characters`、`assets/runtime/webp/enemies`。
- 在文档或 manifest 中标记 placeholder、runtime、concept、source。
- 重构 `index.html` 中的 `skillDock`。
- 重构 `styles.css` 中底部技能栏样式。
- 在暂停界面加入构筑查看入口。

验收：

- 战斗底部不再像一排可点击技能。
- 玩家能理解只有神通是主动按钮。
- 运行时资源路径清楚，不再靠 generated 目录长期运行。

### V0.3.1 正式 UI 第一版

目标：

- 按古朴厚重敦煌风完成第一套可接入 UI。

任务：

- 生成/制作 HUD 残卷。
- 生成/制作灵髓、丹火资源牌。
- 生成/制作神通法印按钮。
- 生成/制作升级三选一卡牌。
- 生成/制作出生选择命格卡。
- 生成/制作剧情对话残卷。
- 生成/制作暂停/设置/轮回结算面板。
- 替换 CSS 里的 atlas-v1 资源路径。

验收：

- 截图一眼能看出敦煌矿物壁画风。
- UI 不压满地图。
- 卡牌不再像网页原型卡，也不偏暗黑仙侠。

### V0.3.2 第一章场景资源包

目标：

- 完成“青丘梦渊”作为第一章正式场景验证。

任务：

- 制作地面基础纹理。
- 制作可随机摆放的小型装饰。
- 制作幻雾池、狐火、残碑、灵井、荒祠、赤裂点位。
- 调整地图 chunk 拼接和远景过渡。
- 让剧情点位与场景主题绑定。

验收：

- 玩家跨屏移动时场景不会出现明显大块拼接。
- 点位和普通摆件能一眼区分。
- 青丘主题和大荒荒境感成立。

### V0.3.3 剧情点位与轮回闭环

目标：

- 让局内叙事成为差异化核心。

任务：

- 每类点位加入 3-5 条短剧情。
- 加入事件选择和后果。
- 加入章节线索计数。
- 加入 Boss 触发条件。
- 加入轮回结算：本世经历、获得线索、解锁提示。

验收：

- 一局内至少能触发一次有意义的剧情事件。
- 结算能让玩家感到本局推进了故事。
- 下一局能看到上一局留下的轻量痕迹。

### V0.3.4 爽感补完

目标：

- 用机制、动效、音效，而不是强数值，提升反馈。

任务：

- 替换美术字飘字。
- 加强剑气、飞符、幻雾、丹火、拾取吸附。
- 增加 UI 动特最小集：资源飞入、选卡展开/收卷、卡牌领悟飞向角色、神通充能/释放、剧情点位呼吸光。
- 增加灵髓/丹火消耗和获得的资源牌反馈。
- 增加暂停“暂/止”印章按压、继续残卷收起的系统 UI 反馈。
- 为每个技能线做至少 2 个明显机制变化。
- 接入第一版正式 SFX。
- 接入探索/敌潮/Boss 音乐层。

验收：

- 拿到卡以后，玩家能马上看出技能变了。
- 命中、击杀、拾取、升级、选卡音效有明显区分。
- 玩家能明确看到灵髓/丹火增加或消耗从哪里发生、流向哪里。
- 选卡、略过、剧情点位、神通释放都有不同的 UI 动效反馈。
- UI 动效不依赖大序列帧，低端设备不会明显掉帧。
- 敌潮增强和 Boss 出现有听觉与视觉压迫。

### V0.3.5 竖屏移动端验证

目标：

- 确认 HTML 竖屏可玩。

任务：

- 触屏移动转盘改为按下时出现。
- 竖屏 HUD 压缩到顶部，卡牌弹层占下半屏。
- 右下神通按钮适配拇指操作。
- 首次触控解锁音频。
- 检查文字溢出、按钮误触、地图遮挡。

验收：

- 手机竖屏可完成 3 分钟局内循环。
- 移动、选卡、神通、剧情点位都能操作。
- UI 不遮住核心战斗区域。
